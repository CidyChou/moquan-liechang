# 墨圈猎场 · 对战模式 MVP PRD

状态：已确认（用户 2026-09-06）  
技术：服务端 Node.js；前端 HTML + Canvas（H5）；后续微信小游戏另开需求  
交付：可运行的 H5 地址

---

## 1. 目标

在现有单机 HTML Demo 玩法上，做 **1v1 对战**，验证「杀敌 → 给对手塞同种怪」是否提升杀敌积极性，并为 IAA 预留广告位（本版不接真 SDK）。

---

## 2. MVP 范围（做）

- 模式：仅「杀到目标数」胜负
- 匹配：点开始 → 自动匹配 1v1
- 视野：各打各的图，只看自己；可看比分/击杀进度
- 本底刷怪：有，规则对齐现有单机 Demo
- 塞敌：我杀 1 个 → 对手地图立刻 +1 个同种敌人
- 升级：三选一，规则对齐单机 Demo
- 受击：扣命；命数数值 **TBD**（测完再定）
- 复活：命尽 → 倒计时 5 秒（界面可展示复活广告占位）→ **自动免费复活**；次数不限；倒计时期间 **对手继续打**
- 反滚雪球（两手都要，数值 TBD）：
  1. 塞敌上限 / 冷却
  2. 落后方补偿（如移速/护盾等，具体形式 TBD）
- 变现：只预留广告位，不接真 SDK  
  - 结算页  
  - 复活倒计时界面（占位）
- 胜负：先达到击杀目标数的一方获胜；击杀目标数 **TBD**

## 3. 非范围（不做 / 后续）

- 限时模式、生存模式（已意向，不进本版）
- 房间码好友房
- 小窗观看对手画面
- 真实广告 SDK / 支付
- 微信小游戏包体与登录
- 排行榜、赛季、段位、观战回放（未确认，默认不做）

## 4. 对战规则（可检查）

| 项 | 规则 | 备注 |
|---|---|---|
| 人数 | 2 | 自动匹配 |

| 本底怪 | 对齐单机 | 验收对照 Demo |
| 塞敌 | 1 杀 → 对面 +1 同种 | 立刻生效 |
| 升级 | 三选一同单机 | 验收对照 Demo |
| 命 | 开局 N 条 | N = TBD |
| 命尽 | 5s 后自动复活 | 免费；不限次；对手不暂停 |

| 失败 | 对方先到 K | 或断线等另条 |

断线 / 重连 / 匹配超时：**TBD**（需补问或首版简单处理）

- 塞敌有上限或冷却（数值 TBD）
- 落后方有补偿（形式与数值 TBD）
- 验收：连续领先一方不能无抑制地把对面塞满到无法操作（具体阈值标准 TBD，测后补）

## 6. 商业化预留（IAA）

- 本版：UI 占位 + 点击/展示路径可走通，**不请求广告 SDK**
- 坑位：结算页；复活 5s 界面
- 后续接 SDK 时，复活可改为「看完再复活」——**本版不实现**

## 7. 技术约束

- 服务端：Node.js（权威逻辑建议在服务端，细节交技术方案，不在此臆测）
- 前端：HTML + Canvas；交付公网可打开的 H5
- 单机 Demo 为玩法参照；对战增量以本文为准

---

## 8. 第一版 / 本周建议裁剪（商业化验证）

只验证三件事：

1. 自动匹配进 1v1 能打完一局  
2. 塞敌钩子手感（杀得越狠对面越难）  
3. 结算 + 复活广告位路径存在  

刻意不做：多模式、好友房、真广告、小游戏、精细数值。命数 N、击杀 K、塞敌冷却/上限、落后补偿 → 先给可调默认，标 TBD，测后改。

---

## 9. 验收标准（通过/打回）

1. 两人可自动匹配进入对局  
2. 各自地图本底怪行为与单机 Demo 无明显冲突（对照 Demo）  
3. A 杀 1 怪 → B 地图出现 1 只同种  
4. 先到击杀目标者胜利并进结算（目标数可配置）  
5. 命尽后 5s 自动复活；期间对方可继续击杀并可能因此获胜  
6. 升级三选一可触发，选项逻辑对齐单机  
7. 塞敌有上限或冷却（可配置）；落后有至少一种补偿（可配置）  
8. 结算页、复活界面可见广告占位；无真 SDK 也可走完流程  
9. 输出可访问的 H5 地址
